## 1. 背景与目标

现有 `0128#cnki_scraper` 是一个 Playwright 驱动的知网爬虫，两个痛点：

1. **只支持知网**——搜索/翻页/验证码/下载逻辑全为 `kns.cnki.net` 写死，换源等于重写。
2. **需手动参与**——验证码自动解被关闭、错误被静默吞掉，实际退化为"等手动 5 分钟"。

**目标**：把它演进为一个**多源、少手动、能被 agent 驱动**的论文采集层，统一产出 `metadata + papers/*.pdf` 喂给 0131 的综述流水线。

本设计是该演进的**第一个子项目**。后续子项目（万方/维普、ncpssd、国际付费大库专用 adapter、0131 集成）各自独立走 spec→plan→实现。

## 2. 范围（YAGNI 边界）

**做（4 件）：**

1. **CNKI 采集模块**：把 0128 现有逻辑整理成干净的 `search + download`，并修好验证码自动解（见 §7）。
2. **接入 scansci-pdf**：作为国际/机构付费侧的现成下载引擎（OA + 出版商 + CARSI/SSO），配置为安全模式。
3. **硬安全闸 RateGuard**：限速 + 每日配额 + 熔断。机构访问下"全校被封"是唯一不可逆风险，必须有。
4. **归一化 + 去重 + 输出契约**：两源元数据并成统一 `metadata.csv`，跨源去重，落 `papers/*.pdf`。

**不做（留后续）：** 万方/维普 adapter、ncpssd 自建、国际付费大库自建 adapter、0131 集成（本期只保证输出契约兼容）、关键词扩展（已有 `keyword-expander` skill）。

## 3. 架构总览与部署拓扑

### 3.1 三层部署拓扑（关键约束的产物）

| 角色 | 机器 | 网络 | 职责 |
|---|---|---|---|
| **开发机** | 主力笔记本 | 全局 Clash（不动） | CC(Claude) 写/改代码，经 SSH 驱动运行机 |
| **运行机** | 校内备用机 | 校园网、**零 VPN/零 Clash** | 执行采集；校园 IP = 机构权限自动生效 |
| **消费端** | （0128 产物） | — | `metadata + papers/*.pdf` 喂 0131/AcadRAG |

链路无冲突：CC↔Anthropic 走 Clash；CC↔运行机走**局域网 SSH**（Clash 默认不劫持内网 IP，用内网地址连）；运行机↔知网/出版商走**校园 IP**。

> 设计含义：**凡机构/校内源的网络请求必须强制直连、忽略环境代理**（httpx `trust_env=False`；Playwright 不传 proxy），保证即便被带代理的父进程拉起，校内源请求仍走校园 IP。

### 3.2 驱动方式：CLI-first

CC 通过 SSH 在运行机上跑 CLI、读回文件（`ssh 运行机 'python -m acq.run --source cnki ...'` → 读 `metadata.csv` / `papers/`）。MCP-over-SSH 别扭，**MCP 留作以后本地交互再加**。

### 3.3 模块布局（瘦身版）

scansci-pdf 已覆盖国际侧 + agent 即编排，故**不自建重型适配器框架**，只保留必要内核：

```
acq/                      # 采集层包（0128 重构进来）
  models.py    # PaperMeta / DownloadResult（源无关数据模型）
  guard.py     # RateGuard：限速 + 每日配额(持久化) + 熔断（硬闸）
  store.py     # 统一 metadata.csv(原子增量写) + papers/ + manifest
  dedup.py     # 跨源去重(DOI 优先，否则规范化标题)
  net.py       # 强制直连的 http/浏览器工厂(trust_env=False / 无 proxy)
  sources/
    cnki.py    # CNKI 搜索+下载(整理自 scraper.py/downloader.py) + 验证码
    scansci.py # 调 scansci-pdf 的薄封装(国际/机构)
  browser.py   # ← 现有，搬入(Playwright+stealth+cookies)
  captcha.py   # ← 现有，搬入并修好(ddddocr 本地解)
  run.py       # 薄 CLI 入口(替代 main.py)
```

## 4. 组件设计

### 4.1 数据模型与输出契约（store.py / models.py）

`PaperMeta` 字段沿用现有 CSV schema，**新增 `source` 与 `dedup_key` 两列**：
`source, dedup_key, title, authors, abstract, keywords, journal, pub_date, doi, institution, fund, cite_count, url, file_path, file_type`

- `metadata.csv`：沿用现有原子增量写（`.tmp`→rename、`utf-8-sig`、按 title 合并），每篇下完即落盘。
- `papers/<safe_title>.<ext>`：下载前 `HEAD`/Content-Type 校验为 PDF 再落盘；按 `dedup_key` 查 manifest 防跨源重复下载。

### 4.2 CNKI 采集模块（sources/cnki.py）

把 `scraper.py`（搜索/专业检索/翻页/列表/详情）+ `downloader.py`（PDF/CAJ）整理为 `search()/download()` 两个清晰函数。**保留专业检索式透传能力**（现有 `--pro`）。验证码逻辑见 §7。

### 4.3 scansci-pdf 接入（sources/scansci.py）

薄封装其 Python API/CLI。**安全配置（强制）**：

- `scihub_enabled = false`（机构正当性）
- `batch_workers = 1~2`（默认 10 会触发全校封禁）
- 所有下载仍经 §4.4 的 RateGuard

> 已接受的取舍：scansci 核心是闭源 Cython 二进制、且经手机构 SSO cookie。laidh 已确认可接受。

### 4.4 硬安全闸 RateGuard（guard.py）

所有 search/download **必经**，agent 无法绕过：

- **限速**：每源最小间隔 + 随机抖动。
- **每日配额**：每源 `max_downloads/day`，**持久化磁盘**，重启不清零。
- **熔断**：识别反爬信号（验证码连续失败、403/429、"访问异常"页）→ 跳闸停该源并显式上报，防止猛打连累全校 IP。
- 风险分档：OA 宽松 / CNKI 中等 / 国际付费大库（后续）最严。

### 4.5 去重（dedup.py）

跨源同篇：有 DOI 用 DOI，否则规范化标题匹配。提供 `dedupe(metas)` 供 agent 在多源 search 后调用。


## 6. 错误处理与可观测性

当前最大问题是**错误被 `except: pass` 静默吞掉**，导致"没生效也不报错"。本期必须：

- 把 `captcha.py` / `browser.py` / `scraper.py` 中所有静默 `except` 改为**至少打日志**（让校园 IP 实测时能看到"弹没弹/弹几次/cookie 存没存上"）。
- **修 cookie 持久化**（`_save_cookies` 系列现全是 `except: pass`）：机构 session 复用可降验证码触发。
- **修验证码检测漏报**：不要"搜索框存在即判无验证码"（SPA 遮罩叠在搜索页上）；穿透 iframe 检测。

## 7. 验证码策略（CNKI tianai blockPuzzle 多缺口滑块）—— 已端到端验证 ✓

**事实（已在校园 IP 实测坐实，2026-06-28）**：
- CNKI 用 tianai blockPuzzle，是**多缺口干扰滑块**（背景画多个假缺口反 OCR），**不是简单单缺口**。
- **ddddocr 弃用**：多缺口下必选错缺口（实测返回 drag 仅 23px、置信 0.979 仍失败；有头模式还会 matchTemplate 崩）。无头/有头给的都是同一个多缺口版，与浏览器 Edge/Chrome 无关。
- **cookie 持久化**只过冷启动 + 压低频率；持续采集到**动态阈值**（非固定计数，laidh 经验约几十篇）后验证码必复现。
- 验证码**人解极易、OCR 解不了** → 用**超级鹰（人力众包）**。

**方案（已验证通过）**：超级鹰 **codetype 9602**（水平滑块拼图，36 积分/次）
- 实测链路：脱 cookie 触发验证码 → 截 `.verify-img-panel`(jpeg) → 9602 返回 `19,110|263,111` → 距离 244px → `_human_like_drag` 拟人拖拽 → **验证码消失、跳搜索页**（CAPTCHA_AFTER=False）。一次成功，正确避开干扰缺口。
- 账号通过环境变量 `CJY_USER` / `CJY_PASS` / `CJY_SOFTID` 配置（勿写入仓库）。

**集成（CaptchaSolver 抽象）**：
1. **检测**：每次导航后统一查（穿透 iframe + overlay 选择器 + `verify` in URL），**动态触发、不靠计数**。
2. **求解**：截 `.verify-img-panel`→jpeg→超级鹰 9602→`x1,y1|x2,y2`→距离=|x2−x1|→`_human_like_drag` 拖拽→`save_cookies`。
3. **省钱**：解错 3 分钟内调 ReportError 退积分；GetScore 监控余额。
4. **兜底**：N 次失败→人工等待（现有 5min）→仍失败→RateGuard 熔断停源告警。
5. **降频**：cookie 持久化 + 限速，减少触发=减少积分消耗。

**保留的现有件**：`_human_like_drag`（轨迹拟人，已验证有效）、cookie 持久化（已验证可过冷启动）、检测逻辑（需补 iframe 穿透）。

**README 纠偏**：写明实际方案 = 超级鹰 9602 + cookie 持久化（删除 ddddocr 自动解的描述）。

**附带 bug（实测发现，待修）**：`downloader.py` 的 `rel_path = file_path.relative_to(file_path.parents[3])` 在 OUT 为浅路径时 `parents[3]` 越界，把"下载已成功"误报为失败（文件其实已落盘）。改为相对 OUT 目录计算。
